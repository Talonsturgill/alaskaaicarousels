The documentation gap check, phase one

Ahead of a pay estimate or a progress submittal, and again at closeout, it reads the documentation you already produce and reports the contract required items it did not find.

Phase one contains no AI. What runs is a list of plain rules, each one naming the contract section it came from. The same run gives the same answer every time, which is most of the reason for building it this way.

Nothing published anywhere says R&M has ever had a funding disallowance, an audit finding or a record dispute. We looked, we found no evidence of one, and nothing on this page suggests otherwise.

Three illustrative runs, one per office. Pick one and step through it.

How it sits in your operation

Three steps. Nothing changes for your field crews and there is nothing for them to install. The change lands on two desks, whoever prepares the submittal and whoever reviews it, and if those two do not change how they work nothing moves. A person stays on every decision the report touches.

Step one

Your construction administration lead writes the rulebook. One plain file per contract, one line per requirement, each line naming the section it came from.

They can read it, argue with it, and change it. If the software went away in a year, that written list would still be worth having.

Step two

The check runs ahead of each pay estimate or progress submittal, and again at closeout. It opens the folders you already fill and writes nothing back into them.

It logs every place it looked, so it can tell you afterward what it was not able to open.

Step three

The report reaches a person. They decide whether a gap matters, chase what is worth chasing, and correct the rulebook when it is wrong.

Nothing here submits, approves, holds or blocks anything. The report is an input to a judgement that stays with the person whose name is on the project.

The report never says a project is complete. It lists the specific items the rules did not find, then names everything it was not able to examine. A wrong flag costs a project manager a minute. A wrong clear costs the check that person would otherwise have done themselves, right before the submittal goes out. So this report never says a project is complete. A requirement the rulebook is missing still shows up as nothing at all, which is why the rulebook has a named owner and a maintenance condition.

Section numbers on this page are illustrative and were written for the demonstration. In the build, every rule carries the section copied out of that project's own contract documents, because a rule nobody can trace back is a rule nobody can argue with.
