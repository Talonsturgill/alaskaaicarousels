    The research behind the offer

    Build plan, alternatives, and dependencies

    Where AI earns its place

    The first slice uses no model call. Rules select relevant experiences from the approved catalog, show the open decisions and prepare a guest-controlled request from explicit party, nights, fly-out and fish choices. The sample uses those explicit records and fixed rules. Natural-language extraction and grounded answers are a pilot test, added only if guests' requests show that the explicit fields miss what they need. Unresolved requests go to your team.

    The systems it needs

    First check the existing website, conditional forms and bought planners against explicit choices, an approved public catalog, relevant open decisions and a structured guest request. Configure a suitable tool when it meets those requirements. A small custom layer is considered only for an unmet requirement. Natural-language extraction and grounded answers are a separate optional experiment, tested against bought tools after the first slice. Live booking calendars, payments and CRM writes are outside the first slice. The board sits beside the existing Book Now and View Pricing & Availability controls on the lodge site. It prepares a pre-booking request and does not replace those controls, read availability or write to a booking system.

    The human decision stays here

    Your team confirms dates, final price, conditions and a feasible trip. Guests review and correct their selected choices before sharing a request.

    Buying, configuring, or building

    A conditional form or rules planner can deliver the catalog board and request. Prefer configuration for those functions. Natural-language preference extraction and grounded answers are the additional AI requirements to test. Yonder lists a Pro plan at $195 a month plus an unpriced configuration service; the available vendor case studies do not establish whether its editable planning and export meet this scope. Demonstrate those requirements before selecting a provider or commissioning custom code.

    Configure a conditional form

    Collect party, nights and experience preferences; produce a structured request using conditional fields. Natural-language interpretation is outside a basic form. The lodge's current platform capabilities are unknown. Prefer this if guests complete the task just as well using explicit choices.

    Configure a rules planner

    Show relevant experiences and open decisions from the approved catalog, with no model call. It requires explicit preferences rather than interpreting a guest's own description. Use this for the board even when an AI layer is added; do not rebuild working site functions.

    Configure a bought tourism assistant

    Existing hospitality assistants provide natural-language answers. Yonder Pro lists at $195 a month, before configuration. Editable preference extraction and the structured request are not established by the available case studies. No absent feature is inferred. Test those requirements and the full price first. Use a bought tool if it meets them.

    A narrow preference-to-plan layer

    Connect editable extracted wishes, approved experiences and a useful lodge request in one guest experience. Adds implementation, evaluation and support work, plus public-catalog upkeep. Build only the unmet requirement after the configuration check and an approved scope. The estimate is conditional, not a custom-build mandate.
