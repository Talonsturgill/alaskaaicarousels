03 The shape of it

How it sits in your operation

01

Your archive is copied once and read only. The tool never writes back to it. If the copy is wrong you delete the copy and nothing else has changed.

02

Someone types the scope and reads what comes back. Every passage carries its document, its date and your role on that contract, and a stale one is flagged before it can be copied.

03

A senior scientist writes the technical approach and signs it, same as today.

04 The boundaries

What it will not do, and these are decisions not gaps

  • It does not write. No technical approach, no past performance narrative, no prose of any kind. Code assembles the sheet. A person writes the proposal. A tool that offered to write it is a tool we would not ship.
  • It does not touch a determination. No finding, no effect call, no species presence or absence. The Fish and Wildlife Service publishes the failure mode inside its own approval of automated bat classifiers, and a peer reviewed evaluation of those same programs found sensitivity as low as 0.01 on a listed species. Those authors recommend a qualified analyst verify automated classifications before presence or probable absence is confirmed. We are taking them at their word.
  • It does not guess a contract number. Those come from a table typed once and tested, which is why 140F0S23A0028 keeps its letter S. A model that is 99 percent right on a contract number is 100 percent wrong on the proposal it lands in.
  • It does not offer the nearest wrong answer. When nothing matches it says so and returns nothing. That behaviour is a test we would write before building, not a promise we make in a meeting.
  • Phase one contains no model at all. It is a search over your own text running on PostgreSQL, which your own data management page lists as in house expertise. A model layer only switches on if it measurably beats the plain search on a test set your coordinator labelled first, and a tie counts as a loss.
